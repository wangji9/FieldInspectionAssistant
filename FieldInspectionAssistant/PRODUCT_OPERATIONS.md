# 产品业务闭环与运维说明（1.2.2 / 业务数据库 v8，录音目录 v2）

设备、任务、缺陷和档案现已合并到“巡检管理”，用户管理位于系统设置。完整流程与数据库关系见 [巡检业务流程与数据关系](docs/inspection-workflow.md)。下文的旧入口名称保留为历史功能说明，实际管理操作从独立设置窗口进入。

文字问答、图片问答和智能体分析已支持输入框“联网”开关，使用真实搜索摘要辅助板端模型并保留来源；详见 [联网搜索使用说明](docs/internet-search.md)。

知识图谱先生成可交互的候选图，筛选后才提交选中的事实及其本体扩展；详见 [图谱抽取与审核](docs/knowledge-graph.md)。

## 一次完整巡检

1. 建立设备、部件和测点，填写安装位置和工况；将真实采集源的通道绑定到测点。
2. 按真实证书追加标定版本；按实际标准和工况追加健康基准。没有有效标定时使用 FS，单位或工况不一致时不自动判定正常。
3. 创建临时任务或周期计划，明确负责人、设备、测点和计划时间。创建时保存检查模板的版本和内容。
4. 负责人开始任务，逐项保存检查结果。拍照、语音和数据分析可通过“关联本次巡检”选择本次记录，不会自动混入其他任务。
5. 每个异常检查项必须有对应缺陷单。跳过必须填写原因；全部跳过标记“未检”，部分跳过标记“部分检查”。
6. 提交后记录不允许覆盖或删除。复核者先校验证据，再写人工结论并确认正式报告。
7. 报告更正追加新版本并填写原因。报告保存确认时的标准、证据、缺陷状态、确认人及 SHA256；后来关闭缺陷不会悄悄改写旧报告。
8. 跟进缺陷分派、整改和复核。报告中仍未关闭的缺陷不会因报告确认而自动关闭。

## 数据与恢复

- 新管理子页面按 30 条分页查询，搜索在数据库执行。
- 草稿删除进入回收站；已提交档案、报告及缺陷历史受到保护。
- 保留期限为 7–3650 天，目前清理范围限于缓存和暂存文件。正式档案、原始采样和证据不会按期限自动删除。
- 清理先预览，再执行，可撤销；恢复时不覆盖原位置已经出现的新文件。
- 备份包含 SQLite 一致性快照、应用数据和引用的外部附件。大文件复制、压缩和哈希在后台进程执行。
- 恢复先检查清单、路径安全、大小、全部文件哈希、数据库完整性、外键和版本；执行前再次备份。安装器等待应用退出后替换数据，失败时恢复原目录。
- 升级包使用与运行版本一致的数据库格式。升级包为 ARM64 ELF，旁边放同名 `.json` 清单，包含 `version`、`schema`（当前为 10）和 `sha256`。历史备份由恢复工具校验并迁移。
- “保存当前程序版本”创建当前版本的已校验副本；从版本记录选择历史版本，准备回滚后再执行“应用已校验版本”。升级回退不会任意降级数据库。
- v6 → v7 的首次上线备份位于板端项目 `backups/product-core`，应将旧数据库和旧程序配对恢复；它与新格式的 v7 备份是两种恢复路径。

## AI 与手工巡检

- 文字、图片、语音会话按账号保存在本地数据库；新会话与历史会话分别保存。
- 文字和图片问答提交同一会话的近期历史（约 12000 字符）；持久化会话不会因模型上下文窗口限制而删除。
- 退出或切换账号会清除上一用户的输入、回答、语音识别和智能体状态；历史记录不能跨用户打开。
- 智能体回答先检查本次图谱引用编号。关联图谱 AI 建议时，还检查来源、关系、原文引文和来源是否撤回。
- 引用一致性校验不等于诊断正确性，最终结论仍由复核人员确认。AI建议不会自动覆盖人工检查结果。
- 模型不可用时，任务、检查项、照片、人工读数、缺陷和正式报告可独立完成。

## 验证与实际使用边界

已在独立板端数据目录验证：设备和测点关联、周期任务补发与幂等、交接、逐项异常关联、回收恢复、报告版本保护与导出、用户隔离、多轮模型推理、附件托管与证据包、备份恢复、损坏包和越界路径拒绝、缓存清理撤销、程序回退以及生产数据库副本迁移。真实六通道采集为 16000 Hz，本次处理约 22 ms、校验错误 0；未经实测不能据此推断长期运行指标。

上线前仍需录入真实设备台账、实际负责人、检查标准、标定和健康基准，并完成连续运行、断电恢复、磁盘接近满载和现场业务验收。六麦当前采样率对应的真实奈奎斯特频率为 8 kHz，显示到 20 kHz 不会产生额外的高频测量数据。


## 1.1.1：权限、会话与采样导出

- 设备台账对有效登录用户只读；只有管理员和主管可修改设备及检查标准。
- 巡检员只能执行本人负责的任务，并修改进行中任务的巡检记录；任务创建、编辑和删除由管理人员执行，交接转移写权限。已登记记录的作者仍可查阅其历史。
- 巡检员只能为本人负责的设备登记缺陷。未分派缺陷的登记人可更正原始内容；分派后通过整改反馈补充内容，原始内容由管理人员维护。只能处理分派给本人的缺陷，复核和关闭由管理人员执行。
- 旧拍照、附件查询、档案编辑、CSV 档案导出与新业务入口使用同一套 C++ 归属规则。无法证明归属的旧记录由主管处理。
- 文字、图片问答把同一会话的近期完整轮次以角色标记的 JSON 传入模型；保存的完整会话与模型上下文长度分别管理。
- 完成回复时保存全文；退出、切换账号和正常关闭窗口前保存尚未提交给定时器的内容。历史按账号搜索和分页，不再依赖推理服务最近若干条结果。保存失败会显示明确提示，空语音会话不生成历史记录。
- 数据分析 → 设置 → 数据与导出 → CSV 范围：整段录音为从开始到点击导出时已经采集的全部样本；当前窗口为最近设置的窗口秒数。两者均在 C++ 后台从原始 WAV 读取，导出所有通道的原始 FS 样本，不应用显示标定。
- CSV 时间戳相对于录音开始，窗口导出不会重新从 0 计时；原始样本时间保留足够精度。相邻 `.meta.json` 保存录音标识、起止帧、行数、采样率和导出范围。导出可取消，取消或读取失败保留原有目标文件。
- 当前没有同步服务器：页面显示“未配置”，同步按钮禁用，本地队列保留。按本轮要求，未进行服务器接入或同步服务器验证。


## 现场拍照布局与状态

- 预览区和右侧控制区等高，填满标题栏下方的可用空间。画面保持比例；底部不再堆叠控件。
- 打开/关闭、拍照和录像按钮固定在右侧顶部，其余摄像头、图像、录像和目录设置在右侧滚动区。窄窗口从右上角“控制”打开面板。
- 未打开摄像头或尚无有效画面时不能拍照、录像；录制或保存期间锁定设备、画质、旋转、目录等设置，停止按钮保持可用。
- 录像中点击“停止并返回”会等待 MP4 保存完成再返回工作台；保存失败时停留在拍照页面显示原因。
- 录像帧率选择不超过实际采集帧率；PNG 关闭有损质量选择。最新照片通过有效性检查后可转入图片问答或关联巡检证据。

## 原始录音数据管理

- 数据分析 → 数据管理：采集停止后自动保存原始录音，也可以“导入 WAV”新增。导入会复制到应用数据目录；失败会回滚目录记录并清理不完整副本。
- 搜索名称、备注、来源或日期，按来源筛选；每页 20 条，全部历史均可分页查询，不再限制最近 200 条。每条的“⋯”提供详情、编辑信息和移入回收站。
- 仅允许修改名称和备注，采样率、通道数、采集时间、原始样本保持只读。并发修改使用修订号检查，过期编辑须刷新后重试。
- 巡检员可以维护本人新采集或导入的录音；主管和管理员可以维护公共录音。历史记录保留原有来源，不凭空指定录制人，由主管或管理员维护。
- 删除需在界面确认，实际移入回收站，可恢复；原始 WAV 和测量明细保留。关联巡检证据的录音不能删除；删除当前分析录音时同时清空图表选择，趋势查询排除回收记录。
- 正在采集、导入、读取或导出时锁定编辑和删除。原始文件缺失会显示状态并禁用分析，详情可查看路径与文件大小。
- 修改、删除、恢复、导入和采集写入 `measurements.sqlite` 的 `recording_events`，不改变已有业务数据库版本。

## 问答与智能体记忆

- 文字问答、图片问答右上角设置，以及智能体设置中提供“记忆（当前会话）”。默认开启，各账号、各模式分别保存到数据库，重启仍然生效。
- 开启时仅使用本人当前会话的近期完整问答轮次，按角色传递给模型。文字与图片问答采用 12000 字符上下文预算，智能体历史采用 6000 字符预算；超出预算时舍弃较早的整轮，不截断单条消息。
- 关闭时仅发送本次输入、当前附件和本次工具返回。历史记录仍保留，可以查看、导出；再次开启会重新使用当前会话的有效历史。若希望从空白上下文开始，使用“新对话”。
- 智能体在任务规划和最终回答两个阶段使用相同的记忆设置，执行期间界面锁定开关；Graph RAG 独立控制，关闭对话记忆不关闭知识图谱检索。
- 错误、未完成、停止或引用校验失败的轮次不作为有效问答记忆。旧智能体历史中紧随失败提示的回答也会被排除。简单确认与对话追问优先直接简洁作答。
- 图片历史只提供既有文字描述，视觉判断仍以本次附件为准；语音转写及朗读保持原文，不使用历史记忆改写识别结果或朗读内容。

## 多模态智能体与文件入口

- 知识图谱 → 构建 → 选择已有对话：统一列出本人保存的文字、图片、语音转写和智能体对话，支持搜索、分页。没有历史时显示空状态，不再弹出空下拉框。抽取只读取有效完整文字轮次，来源记录包含对话类型和标识；图谱更新仍需人工应用候选结果。
- “资料自动抽取”、智能体“添加图片 / 添加录音”使用应用内板端文件选择器，支持目录导航和直接输入完整路径，处理空格、中文与 file URL。它读取的是板端文件系统，电脑本地文件需先传到板端。
- 智能体设置中的工具勾选按账号保存。规划器只接收启用的工具清单，执行前再次校验，模型请求未启用工具会被拒绝。可关闭全部工具，仅使用文字模型回答。Graph RAG 对应图谱检索工具，与对话记忆独立。
- 支持文字任务、图片、音频文件及“录音作为任务附件”。无文字但有附件时也可发送。音频先经 ASR 转写，将本次转写交给规划器；图片由视觉模型分析，最终由文字模型结合本次真实工具结果回答。附件所需工具关闭时明确拒绝提交，不会静默跳过。
- 新任务只使用本次附件，提交成功后清空输入附件。接受的附件复制到本人会话目录，原文件移动后仍可打开历史；历史中的图片可以放大，录音可以手动播放，不自动播放。

## 智能体目录约定

权威索引仍存放于应用数据目录下的 `field_inspection.sqlite`，保留与用户、证据和正式报告的事务关联。新文件布局如下（会话和用户标识使用稳定 ID，不使用显示名称）：

```text
assistant/
  users/<user-id>/
    preferences.json                 # 记忆开关与工具选择的可读副本
    conversations/<conversation-id>/
      session.json                   # 会话、模型、工具和消息快照
      memory/context.json            # 有效上下文；关闭记忆时 history 为空
      attachments/<uuid>.<ext>       # 本次输入的图片和录音副本
```

- SQLite 的 `agent_messages` 附件索引保存相对路径、原文件名、大小和 SHA-256；重开会话从数据库恢复附件，目录 JSON 用于检查和恢复辅助，不替代数据库。
- JSON 使用原子写入；附件按会话复制，账号目录不对其他应用账号开放，文件权限为仅当前 Linux 用户读写。此隔离属于应用账号隔离，操作系统管理员仍有系统级访问权限。
- 完整备份包含上述目录和数据库。既有会话继续兼容读取，保留原记录，不批量修改旧消息或生产资料。

## 1.3.0：设备巡检过程与分析图问答

- 巡检管理先选择设备，再查询该设备的任务、巡检记录、缺陷和资料。新增设备直接打开固定尺寸窗口；任务派发、记录编辑与详情窗口也固定尺寸，并以屏幕可用区域为上限。
- 设备总流程与单次巡检流程按“派发—巡检—记录—整改—复核—完成”展示。记录提交且关联缺陷全部关闭、处理事项全部完成后，该记录显示已完成；仍有任务、整改或处理事项未结束时，总流程继续待完成。
- 点击列表记录进入详情，查看检查项目、文本结论、图片、缺陷及整改事件。处理记录可新增、编辑、软删除、恢复并附图片，修改使用版本号检测并发冲突。权威数据复用 `product_evidence`，与原巡检记录关联，修改前后写入审计。
- 处理图片复制到 `evidence/workflow/<record-id>/<uuid>.<ext>`，保留 SHA-256。替换和移除不删除历史文件。已确认报告仍为不可变快照；后续处理更正不会覆盖已有报告，需要按既有报告更正流程形成新版本。
- 数据分析位于智能助手上方。点击“选图问答”，勾选 1–6 张图，可跨通道、方法选择，再进入文字问答、图片问答或智能体分析。选择时冻结图像和采样/计算上下文，切换页面不会改动已选证据。
- 选图资料保存到 `assistant/users/<user-id>/analysis/<bundle-id>/`，包含单图 PNG、多图编号组合图、SHA-256 和 `bundle.json`。文字模型依据有标记的抽样数据摘要，视觉模型读取编号图像；未标定 FS 不作为电压或声压。图表传入不自动发起推理，用户仍可修改问题后发送。
- 智能体选图任务使用已注册且获准的图像、图谱和联网工具按顺序执行，不重新采集传感器。完整图表上下文随用户消息保存在 SQLite 的会话记录中，并写入本账号辅助快照。数据库版本继续为 8，不重写旧业务数据。

## 1.5.0：整条录音的声学评价报告

- 数据分析新增“评价分析”，位于数据管理左侧。先在录音选择框选择完整录音，填写设备、现场、测点等报告资料，再生成报告；不依赖手动选图、当前显示通道或最近窗口。
- 独立进程读取整段整数 PCM 的全部通道，自动运行 18 类方法，另附 Hilbert 时域包络和整段逐秒 RMS 趋势，共 20 组图。显示曲线/矩阵允许聚合，但变换和统计覆盖所有原始采样；不静默截取时间区间。单文件上限 512 MB，1–8 通道，超限或格式不支持时明确停止。
- 原始录音先核对采样率/通道并记录 SHA-256；处理前后核对文件变化。18 类算法复用既有分析计算定义。独立 Qt/C++ 进程使用原有 MATLAB 风格绘图器生成各通道图组；完整计算数据保存为 plots.json，不只保留屏幕图像。
- 视觉模型分批读取全部图组；文字模型分批整理逐图证据，再依据各批证据、全通道指标、工况和健康基准生成一份综合评价。采用分层上下文适配板端 4096-token 模型；每阶段串行执行，无本地/联网双答案。任一模型阶段失败、图号缺失或结构无效时，不把部分结果保存成完整报告。
- 报告含唯一编号、设备与测点、委托方/报告单位、资料核查表、全部通道指标、逐图物理含义、综合评价、复核建议、审核与更正记录、全部图表附录、原始录音和完整计算结果 SHA-256。导入录音的入库时间标为导入时间，不冒充原始采集日期。
- GB/T 27025-2019 用作报告信息与追溯管理参照；GB/T 17248.1-2022 用于机器设备发射噪声测量方法适用性提示；GB/T 3785.1-2023 用于声级计适用性提示。核查表是软件资料核查，不是标准全文条款复刻或认证声明。未经有效声学校准的六麦数据以 FS / 相对数字量评价，不给绝对声压、声功率或噪声限值合格结论。16 kHz 录音仅能解释到 8 kHz，显示轴到 20 kHz 不产生额外采样信息。
- 报告独立存储于 `acoustic/evaluations.sqlite`（user_version=1），报告、不可变版本、原始录音引用使用外键；业务数据库保持版本 8。文件目录为 `acoustic/reports/<报告编号>/v<版本>/`；计算输入、全量结果、全通道图组和模型批次图保存在 `assistant/users/<用户ID>/acoustic-input/<批次>/`。原始录音仍在 measurements 目录，已被任何报告版本引用的录音不能删除。
- 普通用户只看本人报告；具有复核权限的账号可以查看并审核报告。审核须由另一位实际登录的授权账号完成。更正生成新待审核版本、填写原因，旧版本不覆盖；审核再生成有账号与日期的新版本。可导出待审核草稿，PDF 明确显示状态，不能冒充已审核报告。

## 1.6.0：唤醒式语音对话

- 智能助手的“智能体分析”右侧新增“语音对话”。进入页面不会启动麦克风；点击“开启唤醒”后，使用六麦固件当前唤醒词（默认“小飞小飞”），看到“我在听”后提问。也可点按状态球或输入框麦克风直接说话，或输入文字。离开页面、退出账号或结束对话会关闭录音线程。
- 使用官方六麦 UART 115200 控制协议读取真实硬件唤醒事件，校验帧长度、校验和及握手；不修改唤醒词固件、阈值或重启硬件。控制串口与六通道原始采集互斥。USB UAC 经阵列处理的单声道 16 kHz 用于识别，六通道原始数据仍由数据分析模块处理。
- C++ 非阻塞音频线程与静态编译的 WebRTC/libfvad 语音活动检测，保留短预录，约 0.7 秒停顿后提交；设置可调整 0.5–1.4 秒。未唤醒及播报期间不保存录音；连续对话打开时，回答后继续等待下一句 10 秒，无语音则回到等待唤醒。单次发言最长 20 秒。
- RK1828 的 Qwen3-ASR 与 Qwen3.5 常驻预热，中文 VITS 合成进程在同一账号内复用。模型逐步输出文字并按句合成，播放当前句时合成后一句。冷启动仍需加载模型；切换大型视觉模型后可能需重新预热，不承诺固定延迟。设置显示实测识别、首字和播放启动耗时（不含声卡输出缓冲）；真实口语还包含用户设置的停顿时间。
- 播报只路由到当前 C-Media USB 声卡，默认会话音量 25%，不提高系统音量。再次唤醒或点按状态球可打断；输入框停止按钮停止当前回答。采用轮流收听与播报来避免回录助手声音，不具备持续双向同时收音的回声消除功能。设备断开、被占用或模型/播放失败时明确显示错误，可重新开启，不自动改用其他麦克风或扬声器。
- 双方文字使用稳定列表模型和流式气泡；完成后保存于 SQLite chat_conversations（mode=voice），当前会话记忆可关闭，打断/失败回答不进入有效上下文。历史仅本人可见，支持点击语音条重播或停止、分页、重开及对话/音频附件导出，退出账号清空页面状态。
- 语音媒体位于 assistant/users/<user-id>/voice/<media-session-id>/；input-*.wav 为本次提问，answer-*.wav 为合并回答，part-*.wav 为分句播放文件，数据库消息保存其引用。语音工作目录和文件权限分别为 700/600，备份随 assistant 目录一并保存。仅提供对话解释，不自动操作设备或代替巡检记录。
- 自动验证使用独立 PulseAudio null sink、隔离账号和隔离数据库，避免现场出声；硬件实际唤醒率、远场识别、噪声环境和扬声器听感仍须现场验收。
- 内置第三方 VAD 来源与许可证：third_party/libfvad/UPSTREAM.txt、LICENSE、PATENTS；原始上游 https://github.com/dpirch/libfvad。


## 1.7.0：持续倾听与系统记录查询

- 智能助手移除独立“语音转写”页签，将“语音对话”更名为“语音助手”。原 ASR 识别能力保留给语音输入、语音助手及智能体工具，历史语音转写记录不删除。
- 登录后进入语音助手即开始倾听，无需先说唤醒词。短暂停顿后自动识别与回答；静音等待不会结束会话，播报完继续倾听。说“结束对话”等明确结束指令，或点击结束按钮，立即关闭输入并低音量确认结束；下一次进入开始新会话，已结束内容留在本人历史中。否定句或讨论结束指令不会仅因包含关键词而触发结束。
- 切换页面保留当前语音会话。其他模型、录音、数据采集或播放需要资源时暂停语音助手，完成后自动恢复；暂停/结束及退出账号不会被旧异步回调重新开启。播报期间暂停提问收音，避免录入助手声音；可点按圆球打断。默认音量仍为25%，不提高系统总音量。
- 统一只读 SystemContextService 为文字问答、图片问答、智能体和语音助手提供实时数据库检索。所有 SQL 固定且参数化，不运行模型生成的 SQL、文件路径或业务写操作。角色与任务、巡检记录、缺陷、声学报告的权限每次重新核对；不读取密码、系统密钥或其他账号的聊天。
- 设备名称、编号和中文数字别名可定位设备；同名或编号歧义时要求进一步明确，不取第一个结果。启用对话记忆时支持“它”等上下文指代；明确说“当前设备”时也可使用巡检管理中当前选择的设备。切换账号清理设备选择和语音状态。
- 查询包括设备资料、任务数量与状态、最近最多6条可见巡检摘要和检查读数、未关闭缺陷、处理事件、关联证据与测点。支持今天、昨天、本周、上周、最近N天、指定单日的巡检范围；缺陷数量明确为当前可见状态。摘要有范围，不冒充全量历史导出。
- 声学评价只返回本人或有复核权限可见的报告最新版本，按明确设备名称/编号对应；一般数据分析问题可读取当前分析方法、采样率、通道、单位和指标及近期录音。未关联设备的数据不能自动归属于某设备；未标定FS不能转为声压、电压或限值合格结论。
- 明确的语音设备状态查询可直接播报数据库核对结果，减少规划与生成等待；复杂措施/分析问题依据检索证据交给模型解释。未关闭缺陷优先，任务完成不等于设备正常，历史正常记录不代表实时正常，无资料时明确无法确认。
- 系统依据带SYS编号、查询时间、原记录日期和来源；回复气泡可展开查看依据，并重新校验权限后进入对应设备或具体巡检/缺陷记录。对话数据库保留本次证据快照，重开历史仍可复核当时依据。导出JSON包含证据，Markdown/HTML/纯文本包含来源清单。模型编造不存在SYS引用时不作为有效回答保存。
- 验证使用隔离用户、隔离数据库、虚拟静音麦克风和虚拟静音USB声卡；不将QA设备、缺陷或报告写入正式数据库。真实场景的远场识别和播放听感仍需现场验收。
