# 巡检对象与关联约束

## 软件层级

| 层级 | 职责 |
| --- | --- |
| 现场操作 | QML 负责按设备进入巡检任务、采集、诊断和报告，并显示当前记录 |
| 业务与权限 | 业务服务检查任务状态、记录归属和操作权限，处理巡检、缺陷、报告及关联 |
| 采集与分析 | 摄像头、热像、六麦采集和板端推理提供原始资料、指标与诊断建议 |
| 持久化与审计 | 工程库保管资料、融合和工程报告，巡检库保管任务、签审版本与审计 |

## 现场使用顺序

1. 打开工程，登记设备与测点，并将工程设备绑定至巡检台账。
2. 派发任务，选择设备并开始巡检。在巡检页通过「工程资料」进入本次记录的采集范围。
3. 导入或归档照片、录音、热像、视频与文字。由本次巡检入口归档的资料带巡检记录编号。
4. 选择基准资料生成融合事件。系统按设备、测点、采集时间及巡检记录匹配资料，并进入工程诊断。
5. 复核事件判定，按需关联同一巡检的缺陷，依次完成分派、整改与复核。
6. 在巡检报告中生成工程证据报告或签审正式巡检报告。

独立采集可以在任务创建前进行，后续可通过事件关联到对应巡检。带巡检编号的资料只与同一次巡检的资料融合，融合事件自动继承该编号。历史工程打开时自动添加关联表。

| 对象 | 上游 | 关联规则 |
| --- | --- | --- |
| 设备与测点 | 工程、设备档案 | 工程设备可绑定一个巡检设备档案，原始资料属于一个工程设备和测点 |
| 融合证据包 | 设备、测点、原始资料 | 同设备同测点前后 60 秒内至少两种模态 |
| 诊断 | 融合证据包或人工事件 | 一次推理生成一条诊断结果，证据不足时保持待判定 |
| 事件 | 诊断结果或人工观察 | 记录设备、证据、发生时间及判定，可关联同设备的一次巡检记录 |
| 缺陷 | 巡检发现或人工确认的异常事件 | 缺陷按登记、分派、整改、复核、归档推进。关联异常事件时，设备和巡检记录都须一致 |
| 巡检记录 | 巡检任务与设备 | 记录检查项、现场证据及缺陷，可反查关联的分析事件 |
| 报告 | 工程事件或正式巡检记录 | 工程报告保存证据链，正式报告沿用签审和版本管理 |

人工复核优先于模型判定。人工事件可单独填写发生时间及观察依据。工程诊断可以保存分类建议，巡检分析和报告复核以独立建议显示。巡检记录及正式报告按业务权限读取。
